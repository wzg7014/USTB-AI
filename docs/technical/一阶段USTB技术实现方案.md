# USTB AI教务助手 - 技术实现方案（真实版）

## 🎯 项目概述

基于Qwen2.5-7B-Instruct的教务问答系统，采用RAG检索+LoRA微调的混合架构。通过SSH隧道连接本地Web界面和AutoDL云端AI服务。

**项目状态**：基础功能已实现，但存在连接稳定性问题，需要进一步优化。

## 🏗️ 系统架构

### 整体架构
```
用户浏览器 → Web前端(3000) → Web后端(8001) → SSH隧道 → AutoDL云端服务
                                                    ├── RAG服务(8000)
                                                    └── LoRA推理(8001)
```

### 当前实现状态
- **Web前端**: ✅ 基于ChatGPT-Next-Web，支持流式响应
- **Web后端**: ✅ FastAPI + OpenAI兼容API
- **RAG服务**: ✅ 部署在AutoDL，4621条教务数据
- **LoRA模型**: ✅ 训练完成，167MB适配器
- **SSH隧道**: ⚠️ 连接不稳定，需要手动重启
- **混合API**: ❌ 存在连接问题，返回0字符

## 📊 技术栈

### 核心技术
- **基础模型**: Qwen2.5-7B-Instruct (7B参数)
- **微调方法**: LoRA (rank=16, alpha=32)
- **向量数据库**: Qdrant
- **嵌入模型**: BCE-embedding-base_v1
- **Web框架**: FastAPI + Next.js
- **部署环境**: AutoDL RTX 4090

### 开发工具
- **训练框架**: Unsloth 2024.8
- **SSH工具**: autodl-ssh-remote
- **版本控制**: Git
- **包管理**: pip + conda + npm

## 📈 性能指标（真实数据）

### 当前性能
- **RAG检索时间**: ~2秒
- **模型推理时间**: ~3秒
- **端到端响应**: ~5-8秒
- **数据规模**: 4621条教务文档
- **模型大小**: 7B + 167MB LoRA

### 存在的问题
- **连接稳定性**: SSH隧道经常断开
- **响应速度**: 比预期慢2-3倍
- **错误处理**: 缺乏完善的降级机制
- **监控告警**: 缺乏实时监控

## 🚨 当前问题与限制

### 1. 技术问题
- **SSH隧道不稳定**: 需要频繁手动重启
- **混合API连接失败**: Web API连接器服务异常
- **性能瓶颈**: CPU推理导致响应慢
- **错误处理不完善**: 缺乏优雅降级

### 2. 部署问题
- **启动顺序复杂**: 需要严格按顺序启动服务
- **环境依赖**: 对特定Python环境有强依赖
- **配置管理**: 硬编码较多，配置分散
- **日志管理**: 日志分散，难以统一监控

### 3. 用户体验问题
- **响应时间长**: 用户等待时间过长
- **错误提示不友好**: 技术错误直接暴露给用户
- **功能单一**: 只支持基础问答，缺乏高级功能
