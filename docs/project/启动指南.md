### 📋 **完整启动流程** (2025-08-08 实战验证版)

#### 🚀 **启动顺序：AutoDL服务 → SSH隧道 → 本地服务**

#### 1. AutoDL服务启动 (优先启动)
**在AutoDL环境中按顺序启动以下服务：**

##### 1.1 RAG服务v2.0 (端口8000)
```bash
cd /root/autodl-tmp/ustb-project/services/rag_system
nohup /root/miniconda3/bin/python rag_service_v2.py > ../../logs/rag_service_v2.log 2>&1 &
```
- **状态**: ✅ 正常运行
- **验证**: `curl http://localhost:8000/health`
- **功能**: 4621条USTB教务数据检索，BCE模型向量化
- **预期响应**: `{"status":"healthy","version":"2.0.0","document_count":4621}`

##### 1.2 LoRA推理服务 (端口8001)
```bash
cd /root/autodl-tmp/ustb-project/services/model_inference
nohup /root/miniconda3/envs/unsloth/bin/python ustb_lora_inference_server.py > ../../logs/lora_inference.log 2>&1 &
```
- **状态**: ✅ 正常运行
- **验证**: `curl http://localhost:8001/health`
- **功能**: Qwen2.5-7B-Instruct + USTB LoRA微调模型推理
- **关键**: 必须使用unsloth环境的Python路径
- **预期响应**: `{"status":"healthy","model_loaded":true,"gpu_available":true}`

##### 1.3 混合API服务 (端口8002) ⚠️ **关键服务**
```bash
# 确保日志目录存在
mkdir -p /root/autodl-tmp/ustb-project/logs

cd /root/autodl-tmp/ustb-project/services/model_inference
nohup /root/miniconda3/bin/python api_interface.py > ../../logs/hybrid_api.log 2>&1 &
```
- **状态**: ✅ 正常运行
- **验证**: `curl http://localhost:8002/health`
- **功能**: 协调RAG服务(8000)和LoRA服务(8001)，提供混合回答
- **预期响应**: `{"status":"healthy","lora_service":true,"rag_service":true}`
- **⚠️ 故障处理**: 如果返回500错误，需要重启服务：
  ```bash
  # 查找并杀死进程
  ps aux | grep api_interface | grep -v grep
  kill [PID]

  # 重新启动
  cd /root/autodl-tmp/ustb-project/services/model_inference
  nohup /root/miniconda3/bin/python api_interface.py > ../../logs/hybrid_api.log 2>&1 &
  ```

##### 1.4 Web API连接器 (端口8003)
```bash
cd /root/autodl-tmp/ustb-project/system/web_integration
nohup /root/miniconda3/bin/python web_api_connector.py > ../../logs/web_api_connector.log 2>&1 &
```
- **状态**: ✅ 正常运行
- **验证**: `curl http://localhost:8003/health`
- **功能**: Web前后端API适配器，连接混合API服务(8002)
- **预期响应**: `{"status":"healthy","hybrid_api_status":true}`

#### 2. SSH隧道启动 (本地Windows) ⚠️ **关键步骤**
**方法一：手动启动 (推荐，更稳定)**
```bash
# 启动完整隧道（RAG/LoRA/Hybrid/Web）
ssh -i "<PATH_TO_SSH_KEY>" -p <PORT> -L 8000:localhost:8000 -L 8001:localhost:8001 -L 8002:localhost:8002 -L 8003:localhost:8003 -N <USER>@<HOST>
```

**方法二：自动脚本 (如果SSH密钥配置正确)**
```bash
cd system/ssh_tunnel
python start_tunnels.py
```

- **功能**: 建立本地到AutoDL的SSH隧道
- **映射**:
  - localhost:8000 → AutoDL:8000 (RAG服务)
  - localhost:8003 → AutoDL:8003 (Web API连接器)
- **验证**:
  ```bash
  curl http://localhost:8000/health
  curl http://localhost:8003/health
  ```
- **状态**: 保持运行，Ctrl+C停止
- **⚠️ 故障处理**: 如果隧道脚本卡住，使用手动方法

### 🚨 **常见故障排查指南**

#### 问题1：混合API返回500错误
**症状**: Web界面显示"系统暂时无法处理您的请求"
**解决方案**:
```bash
# 在AutoDL环境中执行（脱敏示例）
ssh -i "<PATH_TO_SSH_KEY>" -p <PORT> <USER>@<HOST>

# 查找混合API进程
ps aux | grep api_interface | grep -v grep

# 杀死进程 (替换PID)
kill [PID]

# 确保日志目录存在
mkdir -p /root/autodl-tmp/ustb-project/logs

# 重新启动混合API
cd /root/autodl-tmp/ustb-project/services/model_inference
nohup /root/miniconda3/bin/python api_interface.py > ../../logs/hybrid_api.log 2>&1 &

# 验证修复
curl http://localhost:8002/health
```

#### 问题2：SSH隧道连接失败
**症状**: `curl http://localhost:8000/health` 连接被拒绝
**解决方案**:
```bash
# 使用绝对路径手动建立单个隧道（示例：RAG 8000）
ssh -i "<PATH_TO_SSH_KEY>" -p <PORT> -L 8000:localhost:8000 -N <USER>@<HOST>
```

#### 问题3：Web后端数据库连接失败
**症状**: 后端日志显示MySQL连接错误
**解决方案**:
- 这是正常现象，系统会自动重试并成功连接
- 如果持续失败，检查数据库服务状态

#### 问题4：前端访问码错误
**症状**: 无法进入聊天界面
**解决方案**:
- 确保使用正确的访问码：`ustb2025`
- 检查前端服务是否在3000端口正常运行
